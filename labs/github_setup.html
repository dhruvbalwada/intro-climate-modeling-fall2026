GitHub on the LEAP hub

Logging in so that git push works — and what to do when it doesn’t

Last week many of you got stuck pushing to GitHub from the hub. The gh-scoped-creds route has two traps: your repo must be added to the app’s list of repositories, and the login expires every 8 hours. Here is a simpler route that you set up once and then forget about.

Everything here is done inside a hub terminal: on leap.2i2c.cloud, File → New → Terminal.

1. Tell git who you are (once)

git config --global user.name "Your Name"
git config --global user.email "your-uni@columbia.edu"

Without this, git commit stops with “Please tell me who you are”.

2. Make a personal access token (once)

A token is a long password that GitHub gives you for use from the command line. Treat it like a password: never paste it into a notebook, a file in your repo, or a chat.

  1. On github.com, click your profile photo (top right) → Settings.
  2. In the left sidebar, scroll to the bottom → Developer settings.
  3. Personal access tokens → Tokens (classic) → Generate new token → Generate new token (classic). (Not the “fine-grained” kind — it works too, but has more knobs to get wrong.)
  4. Note: LEAP hub. Expiration: Custom → 2026-12-31. Scopes: tick the top-level repo box. Click Generate token.
  5. Copy the token now — GitHub shows it only once. Keep it somewhere private (a password manager, or a note on your laptop) until step 3 below is done.

3. Save it on the hub (once)

In the hub terminal:

git config --global --unset-all credential.helper   # clears any leftover gh-scoped-creds setting (harmless if there is none)
git config --global credential.helper store

Now go to your repo and push:

cd ~/climate-modeling-f26-<your-uni>
git push

You will be asked for a Username (your GitHub username) and a Password — paste the token, not your GitHub password. Nothing appears on screen while you paste; that is normal. Press Enter.

That’s it. The token is stored in your home directory on the hub (~/.git-credentials, readable only by you), and every later git push / git pull uses it without asking.

Already cloned with gh-scoped-creds last week? Nothing to redo — your clone uses the same https:// URL. Just run the two git config lines above and push.

4. The everyday loop

After you have worked on a notebook inside your repo folder:

cd ~/climate-modeling-f26-<your-uni>
git add .
git commit -m "Lab 0d: bucket model"
git push

Then check on github.com that the file is there. That repo URL, posted on Courseworks, is your submission.

Prefer buttons? The hub has a Git panel in the left sidebar (the branching-arrows icon). Open your repo folder in the file browser, then in the Git panel: tick the changed files → write a message → Commit → click the cloud-up Push icon. If it asks for credentials, give your username and the token; after the first success it stops asking.

5. When it goes wrong

What you see What it means Fix
Support for password authentication was removed You typed your GitHub password Use the token as the password
Authentication failed Wrong username, or a mistyped/expired token Run git config --global --unset-all credential.helper, redo step 3; if the token is lost, generate a new one
Repository not found (but it exists on github.com) Typo in the URL — or, with gh-scoped-creds, your repo isn’t in the app’s list Check git remote -v; for the app, see §6
Permission denied (publickey) You cloned with an ssh URL git remote set-url origin https://github.com/<user>/<repo>.git
Updates were rejected because the remote contains work The repo changed on the website (e.g. you uploaded a file there) git pull first, then git push
Please tell me who you are Name/email not set Step 1
terminal prompts disabled The Git panel could not ask for a password Push from the terminal once (step 3); after that the panel works

Still stuck? Ask a TA during the lab, or bring it to office hours. Your Lab 0 submission is not late while you are fixing this — but it must work before the first homework.

6. Alternative: gh-scoped-creds

If you would rather not keep a token on the hub, gh-scoped-creds also works — with two things to know.

  1. In a hub terminal run gh-scoped-creds. It prints a link and a code. Open the link, enter the code.
  2. The first time, GitHub asks you to install the app on your account. Choose Only select repositories and pick climate-modeling-f26-<your-uni>. This is the step most people missed.
  3. Created the repo after installing the app, or skipped step 2? Go to github.com/settings/installations → gh-scoped-creds → Configure → Repository access → Only select repositories → Select repositories → add your repo → Save. Then git push works.
  4. The login lasts 8 hours. Next week, run gh-scoped-creds again before pushing.

If you have both set up, git will use whichever it finds first; to switch cleanly to the token route, run the --unset-all line in step 3.
